# Offer Variants Handoff

## Objective
Manage seller-owned Offer price overrides, stock, SKU, media, and active state for each selected combination of `OfferOptionValue` records.

## API Contract
- When admin moderation changes an offer to `approved`, the backend creates the
  Cartesian product of all option-group values. Existing combinations,
  including inactive variants, are retained and not duplicated.
- Generated variants receive an automatic SKU by joining the selected option
  value texts with `-`, preserving Vietnamese text (for example `Xanh-M` or
  `Đen-S`). Media remains nullable, `priceOverride = 0`,
  `availableQuantity = 0`, and `isActive = true`.
- Variant combinations are generated by the backend when an offer is approved;
  users do not create variants or provide their SKU.
- Response returns the created Variant, optional `{ id, secureUrl }` media projection, and selected option values with their group identity.
- `GET /api/offers/:offerId/variants?isActive=true|false` lists variants for the
  authenticated owning seller and optionally filters active state.
- `PATCH /api/offers/:offerId/variants/:variantId` updates non-negative
  `priceOverride`, non-negative stock, seller-owned media, and
  active state. Option-value links are immutable.
- `DELETE /api/offers/:offerId/variants/:variantId` is a soft delete that sets
  `isActive = false`, `priceOverride = 0`, and `availableQuantity = 0`.
- `GET /api/offers/:id` exposes compact `variants[]` with `id`, `sku`, nullable `price`, `availableQuantity`, `isActive`, `optionValueIds`, and nullable `{ id, secureUrl }` media. Variant creation keeps its separate richer response contract.

## Persistence and Validation
- `OfferVariant` belongs to Offer with cascade delete. Its optional media relation uses `SET NULL` when the asset is removed.
- `OfferVariantValue` joins a Variant to an `OfferOptionValue`; deleting an option value is restricted while a Variant references it.
- All selected option values must belong to the owned Offer, and at most one value may be selected from each option group.
- Duplicate combinations are checked against the persisted `OfferVariantValue` links using normalized option value IDs.
- Generated SKU is unique per Offer. Variant creation persists join rows in the same nested Prisma write.
- Optional media must exist. The media URL is always projected from `MediaAsset.secureUrl`.
- Variant list/update persistence includes only relations defined on `OfferVariant`; do not include a nested `variants` relation.

## Cart Integration
- `POST /api/cart/items` accepts optional `variantId`.
- If an offer has variants, buyers must provide `variantId`.
- Cart validates that the variant exists, belongs to the offer, is active, and
  has enough `availableQuantity`.
- Cart item `unitPriceSnapshot` uses `OfferVariant.price` for variant items.
- Active cart response projects only compact variant fields:
  `variantId` and nullable `variantSku`.

## Boundaries
- Option groups and option-value links are not editable in this slice.
- Cart is variant-aware. Cart identity is protected with a transaction-scoped
  PostgreSQL advisory lock for concurrent adds. Checkout revalidates active
  variants, visible option values, and current stock; order items snapshot the
  selected option group/value labels and media URL. Order detail includes
  compact `variant` and `selectedOptions` projections.
